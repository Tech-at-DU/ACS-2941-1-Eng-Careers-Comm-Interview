# Sample Take-Home Project

Many companies now screen junior candidates with a take-home project instead of (or in addition to) a live coding round. Use this as practice for that format — treat the time box and submission requirements as real.

## Project Description

Build a small command-line or web tool that consumes a public API of your choice (e.g. a weather API, a jokes API, GitHub's API) and does something useful with the data — search it, filter it, cache it, or display it in a simple UI. Pick something you can finish well within the time box below rather than something ambitious you'll have to leave half-done.

## Project Requirements

- Time box: 4-6 hours total, spread across however many days you're given
- A working README that includes: what it does, how to run it, and a short "if I had more time" section
- At least 3 automated tests covering your core logic
- Reasonable error handling for at least one failure case (bad input, API timeout, empty result)
- Committed to a public GitHub repo with a real commit history (not one giant commit) — interviewers do look at this

## AI Tool Use

You may use AI coding tools for this project unless told otherwise, but your README must include a one-line disclosure of how you used them (e.g. "used Copilot for boilerplate, wrote the core matching logic myself"). Be ready to explain and modify any part of the code live if asked in a follow-up interview.

## Submission

Submit your repo link via the course tracker.
